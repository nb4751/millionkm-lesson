# 권순영 코치 개인레슨 데이터 관리 — 설치·사용 설명서

## 1. 사용할 방식

이 프로그램은 **코치 PC에서 실행하는 웹서버 + PC/스마트폰 브라우저** 구조입니다. 코치는 로그인 없이 선수 이름을 선택해 파일을 올리고 분석합니다. Garmin에서 내보낸 FIT·CSV 파일을 사용하며 Garmin 계정 비밀번호는 필요하지 않습니다.

기본 코치 화면은 같은 PC의 `http://127.0.0.1:8000`에서만 접근합니다. 이 로컬 주소를 선수에게 보내면 접속할 수 없습니다. 선수가 직접 올릴 때는 공통 주소 하나와 별도 HTTPS 연결을 사용합니다. 기본 공통 모드에서는 활성 선수 이름·기록을 모두 함께 보고, 선수 이름을 선택해 업로드·비교·엑셀 출력을 할 수 있습니다. 주소를 아는 사람에게 이 범위가 공유됩니다. 코치의 수정·삭제·백업 권한은 공유되지 않습니다.

외부 접속은 PC와 프로그램, 인터넷 연결과 HTTPS 연결이 모두 유지될 때 가능합니다. PC가 켜져 있기만 해서는 충분하지 않습니다. 절전·최대절전·재부팅·프로그램 종료·인터넷 장애 중에는 업로드할 수 없습니다. 항상 사용하려면 계속 켜 두는 PC 또는 인터넷 서버가 필요합니다.

## 2. Windows 11 + Miniconda 설치

1. Miniconda 공식 사이트에서 Windows 64비트 설치 프로그램을 내려받아 설치합니다. 비공식 파일이나 인증서 검증 해제를 사용하지 마세요.
2. 저장소를 내려받아 압축을 풀거나 Git으로 복제합니다. 예: `C:\coach\millionkm-lesson`. 압축 안에서 직접 실행하지 않습니다.
3. 시작 메뉴에서 **Anaconda Prompt (Miniconda)**를 엽니다.
4. 다음을 실행합니다.

```bat
cd /d C:\coach\millionkm-lesson
setup_windows.bat
```

스크립트는 `kwon-lesson`이라는 Python 3.12 환경과 패키지, DB 테이블, 정적 파일을 준비합니다. 재실행해도 기존 `.env`와 선수 자료를 덮어쓰지 않습니다. 설치에는 인터넷 연결이 필요합니다.

실제 자료 없이 시험하려면 다음을 실행합니다.

```bat
conda activate kwon-lesson
python manage.py seed_demo
```

가상선수 A/B/C 3명과 활동 18개를 만듭니다. 같은 명령으로 무한 중복되지 않습니다. `APP_DATA_DIR/samples/가상_라이딩_업로드_예제.csv`에도 업로드용 예시가 생성됩니다. 대시보드의 **가상 데이터 체험** 탭을 누르면 표시됩니다. 기본 **실제 선수 기록** 탭에서는 가상 활동이 보이지 않으며, 비교·엑셀도 실제/가상 데이터가 섞이지 않게 구분합니다.

이후 서버를 실행합니다.

```bat
start_windows.bat
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 코치 PC의 로그인 화면 없이 대시보드로 접속합니다. 창을 닫거나 Ctrl+C를 누르면 종료됩니다. 스크립트는 Windows 지원 웹서버 Waitress를 사용하며, 코치 PC의 루프백 주소에만 바인딩합니다. **이 코치용 8000 포트를 외부 HTTPS 터널이나 공유기에 연결하면 안 됩니다.**

수동 개발 실행은 다음과 같습니다. `runserver`는 개발·시험용이며 인터넷에 공개하지 않습니다.

```bat
conda activate kwon-lesson
python manage.py runserver 127.0.0.1:8000
```

## 3. 코치의 사용 순서

1. 대시보드에서 선수를 등록하거나 선수 이름을 선택합니다. 동명이인은 고유 선수 ID로 구분합니다.
2. Garmin Connect에서 해당 선수의 **원본 FIT 또는 CSV를 내보냅니다.** 이 프로그램이 Garmin에 자동 로그인하거나 자동 동기화하지는 않습니다.
3. 업로드에서 대상 선수 이름과 파일을 선택합니다. 선택한 선수가 맞는지 확인하고 저장합니다.
4. 활동 상세에서 파워·심박·케이던스와 파워커브, 훈련부하를 확인합니다. 센서가 없는 값은 미측정으로 표시됩니다.
5. FTP 이력에 코치 설정·Garmin 추정·테스트 측정의 출처와 날짜를 구분해 기록합니다.
6. 선수 비교에서 동일한 기간과 선수들을 선택하고 엑셀을 내려받습니다. 샘플 여부, 종목·체중·측정 장비 차이를 함께 확인하세요.

코치가 파일을 받아 대신 올리는 용도로는 외부 서버가 필요하지 않습니다. 자료를 올리는 선수 이름만 정확히 선택하면 됩니다. 코치 PC를 함께 사용하는 사람은 전체 기록을 볼 수 있으므로 Windows 로그인·잠금과 디스크 접근권한을 유지하세요.

## 4. 공통 주소 하나로 선수 업로드 받기

[배포 안내](docs/배포.md)에 따라 **공유용 8001 서버와 HTTPS 연결**을 먼저 구성합니다. 코치가 공통 HTTPS 주소 하나를 선수들에게 전달하면, 선수는 로그인 없이 이름을 선택하고 Garmin FIT·CSV를 올립니다. 코치가 선수 파일을 받아 대신 올리는 것도 가능합니다.

기본값 `APP_OPEN_PORTAL=1`은 선수 간 기록 공유 방식입니다. 주소를 아는 누구나 모든 활성 선수의 이름·기록을 열람하고 다른 선수 이름으로도 업로드할 수 있습니다. 이름 선택은 본인 인증이 아닙니다. 등록할 대상을 확인하고, 실제 자료를 올리기 전에 선수·보호자에게 공유 범위를 안내하세요. 이 방식에는 업로더 본인 확인이나 선수별 정보 격리가 없습니다.

비공개 운영이 필요하면 `.env`의 `APP_OPEN_PORTAL=0`으로 바꾸고 공유 서버를 재시작합니다. 이 모드에서는 선수별 비밀 링크로 접근 범위를 제한할 수 있습니다. 개인 링크는 별도 비밀번호 없이 접근하는 권한이므로 비공개로 전달하며, 유출 시 폐기/재발급합니다. 개인 링크는 기본 90일 유효하며 재발급하면 이전 링크가 무효화됩니다.

## 5. 파일 준비

ZIP으로 받은 Garmin 파일은 압축을 풀고 `.fit`만 선택합니다. ZIP·실행 파일은 허용하지 않습니다. 서버 업로드 제한은 파일당 20MB입니다. 기록은 최대 20만 개, CSV 한 활동의 시각 범위는 최대 7일입니다. 원본 저장공간 기본 한도는 2GB이며 `APP_MAX_STORAGE_MB`로 조정할 수 있습니다. 공통 포털 업로드는 접속 경로별 시간당 50회로 제한하며, 터널에서는 여러 사용자가 같은 경로로 집계될 수 있습니다. 한도에 걸리면 코치가 확인해야 합니다.

권장 CSV 예시입니다. 단위는 W, bpm, rpm이며 공란과 0은 다릅니다.

```csv
timestamp,power,heart_rate,cadence
2026-10-01T09:00:00+09:00,180,130,85
2026-10-01T09:00:01+09:00,185,132,86
2026-10-01T09:00:02+09:00,190,134,87
```

열을 자동 인식하지 못하면 업로드 화면에서 열 매핑을 지정합니다. 활동목록 요약 CSV에는 시계열이 없으므로 파워커브·NP를 임의 생성하지 않습니다. 동일 파일을 같은 선수에게 다시 올리면 중복으로 거절합니다. 다른 형식으로 내보낸 같은 활동도 코치가 기록 시각을 함께 확인하세요.

## 6. 설정 파일

설치 스크립트는 `.env.example`을 `.env`로 한 번 복사합니다. 실제 `.env`와 비밀키를 Git에 올리지 마세요. 실행 스크립트가 지정한 환경변수는 `.env`보다 우선합니다.

| 변수 | 의미 |
| --- | --- |
| `APP_LOCAL_COACH` | 로컬 코치 자동접속 `1`, 외부 공유 서버는 반드시 `0` |
| `APP_OPEN_PORTAL` | 공통 주소 전체 공유 `1`, 선수별 비공개 링크 방식 `0` |
| `APP_DEBUG` | 로컬 시험 `1`, 외부 공개 `0` |
| `APP_SECURE` | 로컬 HTTP `0`, 신뢰 HTTPS 프록시 뒤 공유 서버 `1` |
| `APP_TRUST_PROXY` | 신뢰하는 프록시가 HTTPS 헤더를 재설정할 때만 `1` |
| `APP_PUBLIC_URL` | 선수에게 전달할 실제 HTTPS 공개 주소 |
| `APP_SECRET_KEY` | 외부 공개 시 필수인 무작위 비밀키 |
| `APP_ALLOWED_HOSTS` | 허용 호스트. 외부 공개 시 실제 도메인과 로컬 호스트 설정 |
| `APP_CSRF_TRUSTED_ORIGINS` | 실제 HTTPS 공개 주소 |
| `APP_DATA_DIR` | DB·업로드 비공개 폴더. 공란이면 기본 `data` 폴더 |
| `APP_MAX_STORAGE_MB` | 원본 업로드 총 저장공간 한도(MB). 기본 `2048` |

`start_windows.bat`는 로컬 코치 모드·로컬 호스트·HTTP를 명시하고 8000 포트에서 실행합니다. `start_share_windows.bat`는 로컬 코치 모드를 끄고 HTTPS 운영 보안을 켜서 8001 포트에서 실행합니다. 두 프로세스는 같은 DB를 사용합니다. 데이터 폴더 위치 변경 시 자료가 자동으로 이동하지 않으므로 서버를 중지하고 [복구 안내](docs/백업_복구.md)에 따라 옮기세요.

## 7. 자동 테스트

```bat
conda activate kwon-lesson
python -m pytest -q
python manage.py check
```

테스트는 임시 DB와 가상 자료를 사용합니다. 클라우드에서의 자동 테스트 통과와 실제 Windows PC·실제 호스팅에서의 동작은 구분해야 합니다. Windows 배치 파일은 본 PC에서 실행해 샘플 업로드까지 확인한 뒤 운영하세요.

## 8. 자주 생기는 문제

- **conda 없음:** Anaconda Prompt에서 실행합니다.
- **Django/Waitress 없음:** 환경 활성화 후 `python -m pip install -r requirements.txt`를 실행합니다.
- **선수가 localhost에 접속 불가:** localhost는 선수의 기기 자신을 뜻합니다. HTTPS 공유 주소를 구성해야 합니다.
- **공유 서버 실행 실패:** 고유한 운영 비밀키와 도메인·HTTPS 주소를 설정합니다. 로컬 코치 모드는 외부 서버에서 끕니다.
- **HTTPS가 반복 리다이렉트:** 터널 대상이 8001인지, HTTPS 전달 헤더와 신뢰 프록시 설정이 맞는지 확인합니다.
- **CSRF/400 오류:** 실제 호스트·HTTPS 주소를 설정하고 재시작합니다. `*`나 CSRF 해제로 우회하지 마세요.
- **FIT 파싱 실패:** 손상되지 않은 원본 Activity FIT를 다시 내보내고 압축을 풉니다.
- **파워 값 없음:** 파워미터가 없거나 기록되지 않았을 수 있습니다. 심박만으로 실제 파워를 만들지 않습니다.
- **재시작 뒤 접속 불가:** 앱과 터널, 인터넷·절전 설정을 확인합니다. 자동 시작은 Windows 서비스로 자동 등록되지 않습니다.
- **DB 잠김:** SQLite 첫 버전은 소규모 운영용입니다. 여러 서버로 확장하려면 DB·저장소 확장 작업이 필요합니다.

오류를 문의할 때 선수 원본, 공유링크 토큰, 생년·주소, 비밀번호를 공개 게시물에 올리지 마세요. 발생 시각과 작업, 개인정보를 가린 오류 메시지로 설명하면 됩니다.
