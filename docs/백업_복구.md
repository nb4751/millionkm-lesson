# 백업·복구와 데이터 소유

프로그램 소스와 로컬 DB·업로드는 코치가 직접 보관할 수 있습니다. 특정 분석 SaaS 계정 없이 운영할 수 있지만, 외부 접속 서비스·서버·디스크의 유지 관리는 운영자가 맡아야 합니다.

## 수동 백업

코치 메뉴의 백업 기능 또는 프로젝트 루트에서 다음 명령을 사용합니다.

```bat
conda activate kwon-lesson
python manage.py backup_data --output D:\coach-backup\lesson-2026-10-28.zip
```

`--output`에는 새 파일 경로를 지정합니다. 기존 파일을 덮어쓰지 않습니다. 서버 명령은 SQLite 온라인 백업으로 DB 스냅샷을 만들고 원본 업로드, 무결성 확인용 `manifest.json`을 ZIP에 담습니다. DB와 업로드 파일을 함께 가장 일관되게 보존하려면 업로드가 없는 시간에 서버를 멈춘 뒤 명령을 실행하세요.

ZIP에는 `db.sqlite3`, `uploads/`의 원본 파일과 파일별 SHA-256 목록이 들어 있습니다. `.env`와 앱 개발용 키는 포함하지 않습니다. 복구 시 같은 운영용 `APP_SECRET_KEY`를 별도 비밀정보 보관소에서 가져와야 합니다. 키가 바뀌면 기존 로그인 세션은 다시 로그인해야 할 수 있습니다.

**백업 ZIP과 엑셀은 암호화되지 않습니다.** 암호화된 외장 디스크 또는 접근이 제한된 암호화 저장소에 옮기세요. 같은 PC의 다른 폴더만으로는 디스크 고장·분실·랜섬웨어에 대비할 수 없습니다. 클라우드에 보관할 때도 개인정보 처리·국외 이전 관련 조건과 계정 권한을 확인해야 합니다.

권장 운영은 매일 백업, PC 밖 별도 저장소 복사, 주기적인 복구 시험입니다. 이 프로그램이 Windows 작업 스케줄러나 외부 백업 서비스까지 자동 등록하지는 않습니다. 작업 스케줄러 등록 시 `kwon-lesson` 환경의 `python.exe` 절대 경로와 프로젝트의 작업 디렉터리를 사용하고 파일명에 날짜를 넣어 덮어쓰기 실패를 피하세요. 실패 여부를 실제로 점검해야 합니다.

## 복구

1. 서버와 관련 업로드 작업을 완전히 중지합니다.
2. 현재 데이터 디렉터리를 별도로 보존합니다. 정상 자료를 바로 덮어쓰지 마세요.
3. 신뢰할 수 있는 본인 백업인지 확인합니다. 알 수 없는 ZIP은 복구하지 않습니다.
4. 빈 임시 폴더에서 아카이브 목록을 검사합니다. 절대 경로, `..`, 심볼릭 링크 등이 있으면 추출하지 않습니다.
5. 프로젝트 폴더에서 `python scripts/verify_backup.py D:\coach-backup\lesson-2026-10-28.zip`을 실행합니다. 경로·SHA-256 검증을 통과했는지 확인합니다. 이 도구는 파일을 추출하거나 기존 DB를 바꾸지 않습니다. 실패하면 복구를 중단하고 다른 정상 백업을 사용합니다.
6. 검증한 `db.sqlite3`와 `uploads/`를 `APP_DATA_DIR`로 복사합니다. `.env`의 `APP_DATA_DIR`가 맞는지 확인합니다. 폴더 접근권한은 서버 실행 계정과 관리자에게만 허용합니다.
7. 해당 백업과 호환되는 프로그램 버전으로 `python manage.py migrate`와 `python manage.py check`를 실행합니다. 업그레이드 시 백업 DB를 복사해 먼저 시험합니다.
8. 서버를 시작한 뒤 코치 로컬 화면과 공유 주소, 활동 수, 파일 다운로드·분석을 확인합니다. 복구가 끝날 때까지 외부 업로드를 재개하지 마세요.

백업은 삭제된 선수 기록도 포함할 수 있습니다. 삭제 요청을 처리할 때 기존 백업 보관기간과 만료·파기 정책도 함께 적용합니다. 해시 검증은 변조 여부를 확인할 참고 자료이며, 암호화나 신뢰할 수 있는 전자서명을 대신하지 않습니다.
