# 분석 지표와 첫 버전의 범위

이 프로그램은 권순영 코치의 개인레슨 기록을 한눈에 살펴보는 첫 버전입니다. TrainingPeaks·WKO와 같은 훈련 분석 제품의 익숙한 지표를 참고하되 해당 제품의 복제, 공식 연동 또는 수치 일치를 보장하지 않습니다. 의료 진단·선수 선발·과훈련 판정 도구로 단독 사용하지 마세요.

## 기록된 값과 계산한 값

- 파일에 파워가 없으면 파워·NP·TSS·파워커브를 생성하지 않습니다. 공란은 0W와 다릅니다.
- 활동 요약 CSV는 요약치만 표시합니다. 초 단위 시계열이 없으면 연속 구간 분석을 하지 않습니다.
- 값이 없는 심박·케이던스·고도·고급 센서 항목은 미측정 또는 데이터 없음으로 봅니다.
- 파일의 UTC 시각은 한국 시간 `Asia/Seoul`로 표시합니다. 시간대 없는 CSV는 한국 시간으로 해석하므로 외국 현지 기록은 시차를 명시한 ISO 8601 시각으로 바꾸세요.
- FIT의 record/session/lap을 읽되 제조사별 독자 필드와 모든 고급 사이클링 다이나믹스의 시각화를 제공하지는 않습니다. GPS 공개 지도는 기본 기능에 포함하지 않습니다.

## 파워

평균·최대 파워는 유효한 시계열을 기준으로 계산합니다. 최대 연속 평균파워(MMP)는 5·10·30초, 1·3·5·10·20·30·60분 구간입니다. 활동보다 긴 구간은 값 없음이며, 기록 공백과 결측값을 무조건 0으로 채우지 않습니다. 정지·불규칙 기록과 장치의 자체 보정에 따라 다른 프로그램과 차이가 날 수 있습니다.

NP는 유효한 30초 이동평균을 4제곱해 평균한 뒤 4제곱근으로 계산합니다. 자료가 짧거나 연속성이 부족하면 생략 이유를 확인하세요. NP, 평균 파워와 FTP는 서로 다른 값입니다. CP·W′·VO₂max·LT1·LT2를 실제 측정 없이 확정하지 않습니다.

FTP가 있을 때 IF는 `NP / FTP`, TSS 추정은 `유효 지속시간(시간) × IF² × 100`입니다. 활동일 이전에 측정한 체중이 있을 때 활동의 W/kg을 계산합니다. 첫 버전은 체중 전체 이력을 보관하지 않으며, 성장기 선수·측정일·장비가 다른 선수의 수치를 단순 서열로 해석하지 마세요.

## FTP와 7개 파워존

FTP는 코치 설정, 테스트 측정, Garmin 추정의 출처와 날짜를 구분해 기록합니다. 파워존은 이 프로그램의 실무용 7영역입니다. 고전적 Coggan 체계의 Z7은 단순 FTP 백분율만으로 정의되지 않는다는 점을 참고하세요.

FTP=250W일 때 정수 W 영역은 다음과 같습니다. 경계값의 중복을 피하기 위해 상한의 정수 이하를 사용합니다.

| 영역 | 범위 | 250W 기준 |
| --- | --- | --- |
| Z1 | ≤55% | 0–137W |
| Z2 | >55–75% | 138–187W |
| Z3 | >75–90% | 188–225W |
| Z4 | >90–105% | 226–262W |
| Z5 | >105–120% | 263–300W |
| Z6 | >120–150% | 301–375W |
| Z7 | >150% | 376W 이상 |

업로드할 때 활동일 이전의 활성 FTP 이력 중 가장 최신 값을 선택해 활동에 저장합니다. 나중에 FTP 이력을 변경해도 저장된 과거 활동의 TSS·존이 자동 재계산되지는 않습니다. 현재 선수 프로필의 기준 FTP와 활동에서 사용한 FTP는 다를 수 있습니다. 과거 활동의 FTP 정책을 바꿔 일괄 재처리하는 화면은 첫 버전에 없습니다.

## 훈련부하와 인터벌

CTL/ATL/TSB 유사 수치는 유효한 TSS를 기반으로 하는 추정 모델입니다. 선택한 조회 기간의 첫날 0으로 초기화하며, TSS가 없는 날은 모델상 0을 가정합니다. 조회 기간을 바꾸면 추정치도 달라집니다. 짧은 관찰기간, 미업로드 활동, 파워 없는 운동 때문에 실제 부하와 다를 수 있습니다. 데이터 없음은 실제 휴식의 증거가 아닙니다.

수동 지정 인터벌은 선택한 구간의 기록과 목표파워를 비교하는 기능입니다. 모든 장치의 자동 인터벌·훈련 처방 인식, 자동 코칭, 피로·부상 진단은 첫 버전의 범위가 아닙니다.

## 운영 확장 항목

공식 Garmin 자동 동기화, 이메일·문자 발송, 여러 코치 간 공유·조직 관리, 고급 생리 모델, 좌우 밸런스·토크 효율 등 고급 센서의 전체 시각화, 원본 재처리 UI, 공개 GPS 지도, 자동 보관기간 파기, PostgreSQL·객체 저장소·다중 서버, 대규모 파일의 비동기 처리 등은 추가 개발과 검증이 필요합니다. 파일 크기와 최대 분석 길이 제한은 서버 오류 및 메모리 사용을 줄이기 위한 첫 버전 정책입니다.

Windows 설치 스크립트와 Docker 배포 구성은 제공하지만 Windows 배치 파일 실행·Docker 이미지 빌드/기동·실제 호스팅 배포는 이번 환경에서 시험하지 않았습니다. 해당 기기·호스팅에서 각각 검증해야 합니다. 자동 테스트 결과와 실서비스 공개 여부는 별도 항목으로 보고합니다.
